## 1. High-Level System Architecture

SAMUDRA implements a **Bounded Collaborative Agent Graph** built on top of LangGraph. In high-stakes maritime navigation and coastal safety, unconstrained agentic autonomy (such as open-ended ReAct loops) is dangerous and prohibited. The architecture strictly separates **cognitive language reasoning** from **deterministic domain computation**.

## 2. Core Architectural Flows

### 2.1 State Flow (`ORCAState`)
The state dictionary traverses nodes sequentially:
1. **Input Stage**: Initialized with `request_id`, `thread_id`, `user_message`, `user_profile`.
2. **Cognitive Stage**: `intent`, `language`, `location`, `time_window`, `missing_fields` populated by Intent Node.
3. **Planning Stage**: `task_plan` generated by Supervisor.
4. **Tool Stage**: `tool_results`, `observations`, `advisories`, `pfz_candidates`, `route_candidates` gathered.
5. **Evaluation Stage**: `risk_assessment` (`Recommendation`) and `confidence` populated deterministically.
6. **Audit Stage**: `evidence` checked; citations verified.
7. **Synthesis Stage**: `response`, `map_layers`, `suggested_followups` composed.
8. **Finalization Stage**: Packaged into immutable `ChatResponse`.

### 2.2 Tool Flow (`AgentToolRegistry`)
Specialist tools are invoked exclusively through the typed `AgentToolRegistry`:
- Tools are declared with `ToolDefinition` and typed `ToolParameter` schemas.
- The LLM supervisor selects tools from the whitelist; it cannot invent arbitrary tools.
- Independent tools (e.g. `marine_weather_forecast` and `fetch_pfz_advisories`) run in parallel.
- All tools return normalized `ToolResult` containing `status`, `data`, `evidence`, and `warnings`.
- Every tool invocation logs execution telemetry (`duration_ms`, `evidence_ids`, `status`).

### 2.3 Evidence Provenance Flow (`EvidenceValidator`)
The non-negotiable architectural rule:
> **Every numerical or factual claim in the final response must be traceable to verified evidence.**
1. Tools attach `EvidenceItem` records with `source_name`, `observed_time`, `valid_from`, and `valid_to`.
2. `EvidenceValidator` audits whether metrics cited in the plan exist in the evidence array.
3. Expired or unverified citations are flagged in `warnings` and downgrade confidence from `HIGH` to `MEDIUM` or `LOW`.
4. If critical data is completely missing, status falls back to `UNKNOWN` with a degraded service notice.

### 2.4 Trace Flow (`AgentTraceLogger`)
The execution trace is public-facing and provides full auditability:
- Records high-level milestones: `"Intent detected"`, `"Specialist tools executed"`, `"Deterministic risk evaluated"`, `"Evidence validated"`, `"Response composed"`.
- **Zero Chain-of-Thought Leakage**: The logger automatically sanitizes and redacts `<think>`, `Thought:`, internal prompt strings, or API secrets before serializing into `ChatResponse.trace`.

### 2.5 Memory & Multi-Turn Context Flow (`MemoryManager`)
Conversations are keyed by `thread_id`:
- **Context Carry-Forward**: Origin harbor, vessel craft profile, and preferred language persist across turns.
- **Selective Updating**: When a user updates temporal parameters ("What about afternoon?"), only `time_window` is replaced, preserving geographic context.
- **Explicit Reset**: Geographic shifts or clear reset commands ("New voyage from Veraval") wipe prior spatial context.
- **Clarification Trigger**: If required fields cannot be resolved from either current message or thread memory, the clarification loop asks the user directly.

## 3. Multilingual Pipeline Architecture

SAMUDRA supports multilingual coastal communities with a unified pipeline:
```
User Message (e.g., Hindi / Marathi / English)
  ↓
Language Detection (ISO code stored in state)
  ↓
Semantic Extraction (Entities normalized to canonical structures)
  ↓
Structured Reasoning & Deterministic Execution (English / SI units internally)
  ↓
Deterministic Risk Evaluation (Immutable state)
  ↓
Response Composer (Synthesizes explanation in user's detected language)
  ↓
Localized ChatResponse
```

### Initial Language Coverage:
- **English (`en`)**: Baseline operational language.
- **Hindi (`hi`)**: National coverage, Gujarat/North-Western coastal communities.
- **Marathi (`mr`)**: Primary coastal dialect focus (Konkan coast, Ratnagiri, Sindhudurg).

## 4. Safety Boundary & Non-Negotiable Rules

1. **Deterministic Primacy**: The LLM **never** decides whether it is safe to sail. Dev 4's Python Risk Engine performs mathematical evaluations of wave height, swell period, wind speed, squall warnings, and craft ceilings.
2. **Safety Invariance**: `ResponseComposer` strictly validates that the LLM has not modified the `RecommendationStatus` (`GO`, `CAUTION`, `NO_GO`, `UNKNOWN`). Tampering triggers an immediate runtime exception.
3. **Untrusted Data Boundary**: All external text (user queries, third-party weather remarks) is treated as raw data, never as prompt instructions, mitigating prompt injection.
4. **Bounded Graph**: Traversal is strictly capped at a maximum of 15 node transitions, eliminating infinite loops.
